# モデルの置き場 — Mac / CUDA の両方で破綻しない設計(2026-09-06)

> どのモデルがどこで動いていて、何を使い、何秒かかるのか。
> 足りないときに何を諦めるのか。それが一目で分かり、その場で変えられること。

4090(離散GPU・VRAM 24GB)と Mac(統合メモリ)は**メモリの性質が根本的に違う**。
同じ UI・同じ設定で両方を扱うために、何を共通の言葉にするかを決める。

## 0. 実測(4090、2026-09-06)— 設計の前提になった事実

| モデル | CPU | CUDA | 判断 |
|---|---|---|---|
| SAM2 vision_encoder(fp32) | 1.568秒 | **0.028秒** | **56倍。GPUに載せる価値が大きい** |
| GroundingDINO int8(204MB) | 1.9秒 | **不可** | `ConvInteger` が CUDA 未実装 |
| GroundingDINO fp16(360MB) | 不可(融合バグ) | 1.87秒 | CPU int8 と横ばい。**載せる意味がない** |
| 生成 klein 4B | 実用外 | 6.1秒/枚 | GPU必須 |

### ここから出た3つの原則

1. **「GPUに載せる価値」はモデルごとに全く違う。** 一律の offload スイッチでは足りない。
   SAM2 は 56倍、DINO は横ばい。**置き場はモデルごとに持つ。**
2. **量子化の版と置き場は結びついている。** int8 は CUDA で動かず、GPU に載せるには fp16 に差し替えるしかない。
   つまり「同じ重みの置き場を変える」のではなく **「置き場ごとに違う重みファイルを持つ」**。
   UI で置き場を変えると **別のファイルのダウンロードが要る**ことがある。これを隠さない。
3. **置き場を変えると他が落ちる。** DINO fp32 を GPU に載せようとしたら、生成(7.8GB)と VLM(8.7GB)で
   埋まっていて cuBLAS の初期化に失敗した。**移動の前に「何が押し出されるか」を見せる。**

## 1. 共通の言葉(両OSで同じ意味を持つもの)

OS で違う物を無理に同じ名前にしない。**両方で意味が通る最小の語彙**だけを共通にする。

| 語 | 意味 | 4090 | Mac |
|---|---|---|---|
| **置き場(where)** | その重みがどこで計算されるか | `cpu` / `gpu` / `remote` | `cpu` / `gpu`(CoreML等) / `remote` |
| **専有(mem_mb)** | その置き場で抱えるメモリ | VRAM の MB | 統合メモリの MB |
| **速度(secs)** | 1枚あたりの実測秒 | 実測 | 実測 |
| **余白(headroom)** | あと何MB置けるか | VRAM 空き | (要調査: 統合メモリの何を見るか) |

**「余白」の定義だけが OS で割れる。** 4090 は `nvidia-smi` の memory.free が正。
Mac は VRAM が無いので別の指標が要る(調査中)。UI ではこの1点だけを OS 別に読み替える。

## 2. 置き場の決め方 — 表で持つ

モデル × 置き場 の**行列**として持つ。セルには「使う重み・速度・メモリ・不能なら理由」が入る。

```
                  cpu                     gpu(CUDA)             gpu(CoreML)
SAM2        fp32 1.57秒 0.5GB       fp32 0.028秒 (要測)      (Macで調査中)
DINO        int8 1.9秒 0.9GB        int8 ✗ ConvInteger未実装  (Macで調査中)
                                     fp16 1.87秒 0.4GB
生成         ✗ 実用外                 6.1秒 7.8GB              (Metal)
```

- **不能なセルは理由付きで✗**にする。「CUDAでint8が動かない」は利用者には分からないので明示する。
- **速い方が自明でないセルは「変わらない」と書く**。DINO を GPU に移させない。
- 既定は **auto**: その機械で入る中で一番速い置き場を選ぶ。入らなければ一段落とす。

## 3. UI の骨子

```
┌ AI の置き場 ─────────────────────────────────────┐
│  GPU  ████████████░░░░░░░░  10.1 / 24.0 GB        │  ← 積み上げ。色はモデル別
│         生成 6.8 │ VLM 8.8 │ 空き 13.9            │
│                                                   │
│  生成 klein 4B      [GPU]  6.8GB  6.1秒/枚        │
│  目利き VLM         [GPU]  8.8GB   —              │
│  マスク SAM2        [CPU]  0.5GB  1.57秒  → GPUで56倍 ⇄│
│  言葉で探す DINO     [CPU]  0.9GB  1.9秒   GPUでも同じ  │
│  似た画像 CLIP       [CPU]  0.6GB   —              │
└───────────────────────────────────────────────────┘
```

- **移動の前にプレビュー**: 「SAM2 を GPU へ → VRAM 10.1→10.6GB、生成は影響なし」。
  押し出しが起きるなら赤で「生成が落ちます」と出す。
- **重みの差し替えが要るときは先に言う**: 「GPU に載せるには fp16(360MB)の取得が必要です」。
- **速くならない移動は勧めない**: DINO の ⇄ は出さないか、灰色で「変わりません」と添える。
- Mac では VRAM バーの代わりに統合メモリの指標を出す(調査中)。**行の並びと操作は同じ**にする。

## 4. データの持ち方

- 実行時の実測 = `GET /api/ai/placement`(実装済み)。
  モデルごとの置き場/メモリ/速度 + `nvidia-smi` で **実際に誰が掴んでいるか**を返す。
- 設定 = `config.gen.*` とは別に **`placement.<model_id> = auto|cpu|gpu|remote`** を持つ(未実装)。
  既定は `auto`。config.rs の defaults に列挙する(未実装の設定を貯めない方針に合わせる)。
- 速度は**測った値だけ**を出す。測っていない組み合わせは「未計測」と正直に出す。推定値を数字で出さない。

## 4.5 4090 で実装済み(2026-09-06)

- `src/ep.rs` に **EP選択を一点集中**。呼ぶ側は `ep::build(path, threads, gpu, what)` だけ。
  OS 分岐(`cuda` → `ort::ep::CUDA` / `metal` → `ort::ep::CoreML`)はこのファイルにしか無い。
- Cargo の `cuda`/`metal` フィーチャに `ort/cuda` / `ort/coreml` を足した(内蔵LLMと足並みを揃える)。
- **GPUに載せるかはモデルごと**: SAM2 は既定でGPU、GroundingDINO は CPU 固定(載せても速くならないため)。
- GPU に載せられなければ**理由をログに出して CPU で続ける**。動かないより遅い方がよい。

### 踏んだ罠: ORT の CUDA プロバイダは CUDA 13 向け

`ort` 2.0.0-rc.13 の同梱プロバイダは **CUDA 13** でビルドされている。この機械は CUDA 12.4 だったので
`libcublasLt.so.13` が見つからず、**黙って CPU に落ちていた**(EP は既定で失敗を握り潰す。
`error_on_failure()` を付けて初めて理由が出た)。CUDA 13 のランタイム(cublas/cublasLt/cudart)と
cuDNN 9 を入れて解決。取得は `tools/get_cuda_libs.sh`(約1.4GB)。

動的リンカのパスはプロセス開始前に決まるので、後から設定しても効かない。起動方法(deploy.sh / .app /
systemd)ごとに面倒を見ると漏れるので、**`engine/cuda/lib` があれば自分を起動し直す**ようにした
(`ep::adopt_gpu_libs`)。置くだけで効く。無ければ何もしない。

### 効果(RTX 4090 実測、画像読み込み〜ポリゴン化〜保存を含む端から端)

| | CPU | GPU |
|---|---|---|
| マスク(クリック1回) | 0.95秒/枚 | **0.057秒/枚(16.7倍)** |
| 言葉で自動マスク(DINO CPU + SAM2 GPU) | 3.5秒/枚 | **2.35秒/枚** |

自動マスクが1.5倍止まりなのは、残り時間のほとんどが CPU 固定の DINO(1.9秒)だから。**次に効くのはそこ**。

## 5. Mac 側の未確定(調査依頼中)

1. ort 2.0.0-rc.13 で CoreML EP が使えるか。フィーチャ名と Session への渡し方
2. SAM2 / DINO int8 の CPU vs CoreML の実測。**int8 が CoreML で動くか**
3. 統合メモリで「余白」に相当する指標(sudo 無しで取れるか)
4. CoreML 以外の選択肢(MPS / ANE)の有無
5. 生成(sd.cpp Metal)と ONNX のメモリ競合が Mac でも起きるか

この5つが埋まったら §1 の「余白」と §2 の行列の Mac 列を確定させ、実装に入る。

## 6. 実装の順(4090側が担当)

- P1: `placement.<model_id>` を config に追加し、`auto` の判定を1か所に集める
- P2: ORT のセッション構築で EP を選べるようにする(CUDA / CoreML / CPU)。**OS ごとの分岐はここだけに閉じ込める**
- P3: 置き場ごとの重み(int8/fp16)の取得と切り替え
- P4: UI(積み上げバー・移動プレビュー・不能セルの理由表示)
