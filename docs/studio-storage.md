# fluent_scene エディターの画像保存

エディターで描画した最終結果を PNG に焼き込み、通常の画像として保存する。元画像のファイルと編集履歴は、保存処理では変更しない。ギャラリーの表示時にフィルタグラフや GLSL を実行することはない。

## ファイルと ID

```text
store/images/<先頭2文字>/<元SHA>.png          元画像（元の拡張子を維持）
store/meta/<先頭2文字>/<元SHA>.json           元画像の情報・個別編集履歴
store/images/<先頭2文字>/<加工SHA>.png        描画済みの最終画像
store/meta/<先頭2文字>/<加工SHA>.json         加工画像の情報・元画像への参照・レシピ
store/thumbs/<先頭2文字>/<加工SHA>.m.jpg      120 px
store/thumbs/<先頭2文字>/<加工SHA>.jpg        360 px
store/thumbs/<先頭2文字>/<加工SHA>.p.jpg      1080 px
store/studio_assets/<アセットSHA>.png        追加画像・テクスチャ（JPEG/WebP も可）
```

加工 SHA は保存する PNG ファイル全体の SHA-1。元画像の SHA・元の編集リビジョン・レシピから作った識別情報を PNG の `tEXt` チャンクに入れるため、同じ画素でも異なる出自の画像が混同されない。PNG の解像度と透明度は維持する。

同じ結果・元画像・レシピを再保存した場合は、既存の加工画像を再利用する。その加工画像が後から個別編集されている場合は、既存の編集履歴を保持して別の画像を保存する。

## 加工画像のメタデータ

元画像と同じ `source`、出典や権利情報を引き継ぎ、新しい `ingested` 時刻で通常の画像索引に登録する。加工結果の画素はすでに確定しているので、その画像に実行用の `edits` 履歴は付けない。

```json
{
  "sha1": "加工画像のSHA",
  "ext": "png",
  "w": 1280,
  "h": 960,
  "source": "upload:写真",
  "studio": {
    "version": 1,
    "source_sha": "編集開始時の画像SHA",
    "source_edits": [],
    "source_edits_rev": "12文字のリビジョン",
    "identity": "出自とレシピのハッシュ",
    "recipe": {
      "version": 1,
      "photo_edits": [{"op": "adjust", "params": {"exposure": 0.2}}],
      "graph": {
        "n": [{"i": "n1", "t": "src", "k": "smp"}, {"i": "n2", "t": "out"}],
        "e": [["n1", 0, "n2", 0]]
      },
      "sceneYaml": "エディターが書き出したシーン定義",
      "time": 0,
      "width": 1280,
      "height": 960,
      "assets": [
        {
          "kind": "source",
          "key": "upload-1",
          "name": "追加画像.png",
          "data": "/studio-assets/アセットSHA.png"
        }
      ]
    }
  }
}
```

`graph.n` に入力・フィルタ・出力などのノード、`graph.e` に接続を保存する。`source_edits` は編集開始時に元画像へ適用されていた履歴のスナップショット。元画像への参照と合わせて再編集の出発点を記録する。

`recipe.photo_edits` は、今回のエディター内で写真調整に使った履歴。露出・自動補正・切り抜きなどを元ファイルに適用した後、fluent_scene のフィルタグラフを描画する。元画像に保存されている履歴とは独立して保持する。

追加画像は送信時の data URL を専用ファイルへ分離し、レシピにはローカル URL を残す。共有できる SHA 単位で保存するため、画像メタデータに大量の画像データを埋め込まない。

## 保存 API

`POST /api/studio/{source_sha}/save` に multipart の `image`（PNG）と `recipe`（JSON）を送る。`recipe.source_edits_rev` がある場合は元画像の現在の履歴と照合する。保存直前にも履歴を確認し、途中で変更されていたら `409` を返す。

PNG は最大 64 MiB、各辺 8192 px 以下、3200 万画素以下。追加画像を含むレシピは最大 16 MiB、追加画像は 64 件以下。ノードは 512、接続は 2048 以下。元画像の存在、PNG の読み取り、サイズ、追加画像の参照も検証する。

重い画像処理はバックグラウンド用スレッドで行い、PNG・サムネイル・プレビューを準備した後、短いロック中にメタデータと索引を登録する。成功時は `{ok, sha1, meta, reused}` を返す。以後の表示は保存済みの画像ファイルを読む。

## 写真調整の一時プレビュー

`POST /api/studio/{source_sha}/preview` に JSON `{edits: [...], source_edits_rev?: "12文字"}` を送ると、写真調整を適用した原寸 PNG を `Cache-Control: no-store` で返す。元ファイルへ送信された履歴だけを適用し、現在保存されている履歴を重ねて適用することはない。

この処理はファイル・メタデータ・画像索引を変更しない。結果の PNG は、同じ写真調整画面にある fluent_scene の入力画像になる。写真調整とフィルタグラフを合わせた最終結果は、通常の保存 API で確定する。

履歴は最大 64 操作、リクエストは 1 MiB。調整値・フィルタ名・回転・反転・切り抜き範囲を検証し、元画像の版が途中で変われば `409` を返す。原寸処理は最大 2 件ずつ実行する。

## 「原本に戻す」の参照解決

焼き込み済み画像は `edits` が空でも加工されているため、履歴を空にするだけでは原本へ戻らない。

`GET /api/original/{sha1}` は `studio.source_sha` と既存のフォルダフィルタの `filter_source_sha` を順にたどり、最初の元画像を返す。

```json
{"ok": true, "sha1": "最初の元SHA", "meta": {}, "derived": true, "chain": ["加工SHA", "中間SHA", "最初の元SHA"]}
```

この API は読み取り専用で、加工画像も元画像も削除・変更しない。元画像の現在の履歴は `meta` に含まれる。画素そのものの原本は `/img/{sha1}` から取得する。参照の循環・不正な参照は `409`、元ファイルがない場合は `404`。探索は最大 64 画像までに制限する。
