# fluent_scene エディターの画像保存

「適用」は、選択中の画像の編集履歴を更新する。画像 ID とギャラリーの件数は増えない。元画像のファイルは上書きせず、描画済みの最終 PNG を専用領域に保存する。通常の閲覧ではその保存済み画像を読み、fluent_scene のフィルタグラフや GLSL を再実行しない。

## ファイルと ID

```text
store/images/<先頭2文字>/<画像SHA>.<元拡張子>  不変の元画像
store/meta/<先頭2文字>/<画像SHA>.json          同じ画像の情報と編集履歴
store/studio_renders/<先頭2文字>/<描画SHA>.png       加工済みの原寸 PNG
store/studio_renders/<先頭2文字>/<描画SHA>.json      レシピと入力状態
store/studio_renders/<先頭2文字>/<描画SHA>.120.jpg   保存時に作る表示用画像
store/studio_renders/<先頭2文字>/<描画SHA>.360.jpg
store/studio_renders/<先頭2文字>/<描画SHA>.1080.jpg
store/studio_renders/<先頭2文字>/<描画SHA>.1600.jpg
store/studio_assets/<アセットSHA>.png          追加画像・テクスチャ（JPEG/WebP も可）
```

画像 SHA は従来どおり元ファイルの ID。描画 SHA は内部ファイルの識別子で、通常の画像索引へ新規登録しない。元の `sha1`、`ext`、`w`、`h`、`bytes`、`source`、取り込み日時は保持する。加工後の寸法は描画側の JSON に保存する。

描画 SHA は、レシピと入力の識別情報を `tEXt` チャンクへ付けた PNG 全体の SHA-1。原寸と透明度を保持する。同じ画像・入力・レシピ・画素を再保存した場合は既存ファイルを再利用し、現在の履歴の末尾も同じ描画なら履歴を追加しない。

## 同じ画像の編集履歴

通常の写真調整と同じ `edits` 配列に、確定済みの描画への参照を追加する。

```json
{
  "sha1": "選択中の画像SHA",
  "ext": "png",
  "w": 1280,
  "h": 960,
  "edits": [
    {"op": "adjust", "params": {"exposure": 0.2}},
    {"op": "studio", "params": {"render_sha": "専用領域の描画SHA"}}
  ]
}
```

表示時は最後の `studio` 操作が指す PNG を読み、それより後の写真調整だけを適用する。それ以前の調整とフィルタは PNG に反映済みなので、重ねて計算しない。末尾が `studio` なら原寸 PNG と保存済みの表示用 JPEG をそのまま使える。履歴のリビジョンが通常のサムネイル・表示キャッシュのキーになる。

「一手戻す」は履歴を一つ戻し、「原本に戻す」は履歴を空にする。履歴参照を変える操作なので、元画像や確定済み PNG の画素を破壊しない。過去のバージョンが作った別 ID の加工画像も、そのまま保持する。

## レシピと再編集

描画側の JSON は次の情報を持つ。`source_sha` はエディターの入力画像、`target_sha` は適用先の画像で、通常は同じ SHA。過去の加工画像を元の入力から再編集する場合などは異なることがある。

```json
{
  "version": 2,
  "render_sha": "描画SHA",
  "target_sha": "適用先の画像SHA",
  "source_sha": "入力の画像SHA",
  "source_edits": [],
  "source_edits_rev": "入力履歴の12文字のリビジョン",
  "w": 1280,
  "h": 960,
  "recipe": {
    "save_mode": "in_place",
    "version": 1,
    "photo_edits": [{"op": "adjust", "params": {"exposure": 0.2}}],
    "graph": {
      "n": [{"i": "n1", "t": "src", "k": "smp"}, {"i": "n2", "t": "out"}],
      "e": [["n1", 0, "n2", 0]]
    },
    "sceneYaml": "エディターが書き出したシーン定義",
    "time": 0,
    "assets": [{"kind": "source", "key": "upload-1", "name": "追加画像.png", "data": "/studio-assets/アセットSHA.png"}]
  }
}
```

`source_edits` は保存時の入力画像の履歴の控え。`recipe.photo_edits` は今回の写真調整に実際に使った履歴で、元ファイル、または履歴中の確定済み描画から復元する。その結果へ fluent_scene のグラフを適用する。

`GET /api/meta/{sha1}` は、最後の `studio` 操作に対応する JSON を `studio_edit` に展開し、履歴内の位置 `index` と以後の写真調整 `tail_edits` を付けて返す。このフィールドは応答時に作り、元画像のメタデータには重複保存しない。従来の別 ID 方式の来歴 `studio` は変更せず、新しい編集は `studio_edit` で区別する。

追加画像の data URL は専用ファイルへ分離する。レシピには同一サーバーの参照 URL を保存し、再編集で読み込む。大きな画像データを通常のメタデータに埋め込まない。

## 保存 API

`POST /api/studio/{選択中の画像SHA}/save` に multipart の `image`（PNG）と `recipe`（JSON）を送る。成功時は `{ok, sha1, meta, reused}` を返し、`sha1` はリクエストの選択画像と同じになる。

`recipe.save_mode: "in_place"` は必須。メタデータ応答の `studio_save_mode: "in_place"` と合わせ、古い画面・古いサーバーとの混在時に誤って別 ID の画像を作らないために照合する。

`recipe.input_sha` は省略時に選択画像と同じ。`source_edits_rev` は入力画像、`target_edits_rev` は適用先画像の現在の履歴と照合する。入力と適用先が同じで後者が省略された場合は前者を使う。保存開始時の両方の履歴は確定直前にもロック内で確認し、途中で変更された場合は `409` を返す。リビジョン指定は同じ描画を識別するハッシュには含めない。

PNG は最大 64 MiB、各辺 8192 px 以下、3200 万画素以下。追加画像を含むレシピは最大 16 MiB、追加画像は 64 件以下。ノードは 512、接続は 2048 以下。画像の存在・寸法・読み取り・追加画像の参照も検証する。

重い画像処理はバックグラウンド用スレッドで実行する。PNG・レシピ・表示用画像を準備してから、短いロック内で同じ画像のメタデータと既存の索引行を更新する。競合で使われなかった内部ファイルは画像件数に影響せず、同じ内容の保存で再利用できる。

## 写真調整の一時プレビュー

`POST /api/studio/{入力の画像SHA}/preview` に JSON `{edits: [...], source_edits_rev?: "12文字"}` を送ると、写真調整を適用した原寸 PNG を `Cache-Control: no-store` で返す。送信された履歴だけを使い、保存済みの現在の履歴を追加で重ねない。履歴に `studio` 操作があれば最後の確定済み描画から以後の操作を適用する。

この処理はファイル・メタデータ・画像索引を変更しない。結果は同じ写真調整画面にある fluent_scene の入力になる。調整とフィルタグラフを合わせた最終結果は保存 API で確定する。

履歴は最大 64 操作、リクエストは 1 MiB。調整値・フィルタ名・回転・反転・切り抜き・内部描画参照を検証する。入力の版が途中で変われば `409` を返す。原寸処理は最大 2 件ずつ実行する。

## ZIP での保存・復元

書き出した ZIP では、通常の画像ファイルと `meta/` のサイドカーに加え、参照中の描画 PNG・レシピ・追加画像を `.fluent_gallery/` の内部領域に入れる。編集履歴から必要なファイルだけをたどり、共通の添付は一度だけ保存する。表示サイズ別の JPEG は再生成できるため含めない。

取り込み時はこの内部領域を通常の画像収蔵から除外する。添付の ID・形式・参照・サイズを確認して内部保存先へ復元した後、通常の画像とサイドカーを取り込む。1 枚を書き出して戻した場合、加工結果を保持した 1 枚として復元される。

## 過去の加工画像からの原本参照

`GET /api/original/{sha1}` は、旧方式の `studio.source_sha` とフォルダフィルタの `filter_source_sha` を順にたどる。新方式の `studio_edit.source_sha` はたどらないため、同じ ID への編集で循環は発生しない。

```json
{"ok": true, "sha1": "最初の元SHA", "meta": {}, "derived": true, "chain": ["旧加工SHA", "最初の元SHA"]}
```

この API は読み取り専用。新方式だけで編集した画像では自分自身を返し、履歴のクリアで原本表示へ戻れる。画素そのものの原本は `/img/{sha1}` から取得する。参照の循環・不正な参照は `409`、元ファイルがない場合は `404`。探索は最大 64 画像まで。
