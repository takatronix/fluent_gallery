# 顔ID設計 — 本人判定を「数学」に置き換える

作成: 2026-09-03 (Fable)
状態: 設計のみ・未実装
目的: 「特定の人物だけ集める」の本人判定を、LLM(有料・確率的)から顔埋め込み距離(無料・決定的)へ移す。
同時に per-member タグ(karina/miyeon等)を**顔を見た根拠付き**で付ける。

## なぜやるか(2026-09-03の実測)

- LLM判定(Haiku)は有名人ならかなり当たるが、①新人/マイナーは知らない ②そっくりさんを稀に通す ③1枚$0.001かかる
- crawl.tagsは「そのクエリで見つけた」という出自タグであり、本人保証がない(Karinaクエリで来たWinterにkarinaが付く)
- 蒸留ゲート(CLIP)は「傾向」しか見れない。CLIPは同一人物の識別には弱い — 顔専用埋め込みが必要

## モデル(ダウンロード不要の可能性が高い)

InsightFace buffalo_l 一式(ONNX)を使う:
- **det_10g.onnx** (SCRFD): 顔検出+5点ランドマーク
- **w600k_r50.onnx** (ArcFace r50): 112x112アライン済み顔 → 512次元埋め込み(L2正規化)

**Deep-Live-Cam導入時に取得済みの可能性大**: `~/.insightface/models/buffalo_l/` を最初に確認。
無ければHuggingFaceから2ファイル(~180MB)。実行は既存のort(clip-visionと同じ流儀、onnx.rsに追加)。
顔アライン(5点→112x112相似変換)は自前実装(20行程度、umeyama)。

## データモデル

```sql
CREATE TABLE IF NOT EXISTS faces (
  person TEXT,      -- 表示名(小文字: karina)
  album  TEXT,      -- 所属フォルダ(グループ)。''=グローバル
  sha1   TEXT,      -- 参照元画像
  emb    BLOB,      -- f32 LE 512次元(embと同じ流儀)
  bbox   TEXT,      -- 参照元内の顔位置(監査用)
  PRIMARY KEY(person, sha1)
);
```
- 1人あたり参照3〜8枚を推奨(角度・髪型違い)。centroidではなく**全参照とのmax cosine**で判定(髪型変化に強い)
- しきい値(ArcFace実績値、要実測調整):
  - `FACE_SAME = 0.42` 以上 → 本人確定(タグ付与・LLM省略可)
  - `FACE_DIFF = 0.25` 未満(登録全員に対して) → 別人確定(却下 or 無タグ)
  - 中間帯 → LLM判定へフォールバック(従来動作)

## パイプライン統合(判定の新しい階段)

```
候補画像
 → 決定的ゲート(サイズ/pHash/ブレ露出)      無料
 → 蒸留ゲート(CLIP傾向)                    無料
 → ★顔ゲート(登録があるフォルダのみ)        無料
     顔なし → LLMへ(風景/後ろ姿はLLMが判断)
     本人一致 → 採用側へ+personタグ(LLM省略 or 画質のみLLM)
     全員不一致 → 却下「登録メンバー不一致(顔ID)」
     中間帯 → LLMへ
 → LLM目利き(最後の砦・呼ぶ回数が激減)      有料
```

期待効果: 人物フォルダのLLM呼び出しを7〜9割削減、そっくりさん混入ゼロ化、
新人でも参照さえあれば判定可能(LLMの知識カットオフ非依存)。

## 登録UX(最小)

1. **ライトボックス**: 顔を検出して枠表示 → 枠クリック「この顔を◯◯として登録」(フォルダのメンバー名リスト+新規)
2. **フォルダ設定**: メンバー一覧(名前・参照枚数・削除)。「収蔵済みから自動候補」ボタン=
   フォルダ内の顔をクラスタリングして「この人を登録しますか?」を提案(k人分)
3. 遡及スキャン: 「メンバータグを付け直す」ボタン → フォルダ全画像を顔ゲートに通し
   per-memberタグ付与+不一致を確認箱へ(非破壊)

## API/MCP

- `POST /api/faces/enroll {album, person, shas[]}` — 参照登録(顔検出→埋め込み→faces表)
- `GET  /api/faces?album=` — メンバー一覧+参照数
- `POST /api/faces/scan {album}` — 遡及スキャン(タグ付与・ジョブ)
- `DELETE /api/faces {album, person}` — メンバー削除
- MCP: 同名ツールを gallery_mcp.py に追加

## 実装フェーズ

- **P1 エンジン**(Rust): onnx.rsにdet_10g/w600k_r50ロード+アライン+embed。faces表。enroll/一致判定関数。テスト=同一人物2枚>0.42、別人<0.25を確認
- **P2 登録UI**: ライトボックス顔枠+登録メニュー、フォルダ設定メンバー欄
- **P3 収集統合**: crawl.rsの顔ゲート+personタグ+却下理由
- **P4 遡及+フィルタ**: scanジョブ、memberチップでフィルタ(tags経由なので実質できている)

## リスク/割り切り

- 横顔・オクルージョン→検出失敗→LLMへ(従来精度は維持される、劣化しない設計)
- 子供時代の写真等は距離が伸びる→中間帯→LLM
- 同一グループ内の姉妹的そっくり(双子)は閾値では割れないことがある→参照を増やす+LLM併用
- 実在人物の顔照合は**本人のための収集ツール内の私的機能**に留める(公開サービス化する場合は要法務検討)
