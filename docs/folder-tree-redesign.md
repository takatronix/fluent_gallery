## 1. 今日ユーザーが実際に詰まった順序(全部実話)

1. 「AV女優」というフォルダを作り、目標に「河北彩花」と入れた → **1枚も集まらない**
2. 作り直そうとして同じ名前で作った → **何も起きない。エラーも出ない**
3. 「フォルダができていない」と判断 → 実際にはフォルダはあり、0枚だった
4. 「フォルダ +」で入れ物を作ろうとした → **収集タスクが生まれた**(入れ物ではない)
5. `AV女優/河北彩花` と書けば入れ物ができると知る → **画面のどこにも書いていない**

**5つのうち3つは修正済み。残り2つは作り直しの対象。**

## 2. 根本の問題: 「フォルダ」が2つの意味を持っている

| 画面上 | 実体 | 作れるか |
|---|---|---|
| `K-POP_Idol` (三角つき) | **入れ物(グループ)**。タスクの `folder` 欄に名前が書かれていれば現れるだけ | 空では作れなかった |
| `aespa` (地球アイコン) | **収集タスク**。名前がそのまま識別子でありバケツ名 | 「フォルダ +」で作れる |

同じ「フォルダ」という語で呼び、同じ木に並べ、同じ ＋ ボタンの先にあるのに**別物**。
ユーザーが「入れ物を作ってから中身を作る」という当たり前の順序を取れない。

## 3. 名前が識別子であることの副作用

`album_slug` は名前を `store/albums/<名前>.json` と `crawl:<名前>` に直結させている。よって:

- **同名は作れない**(グループが違っても不可。`folder` は識別子に入らない)
- **記号違いが潰れる**。英数字/`_`/`-` 以外は全部 `_` になるので `A/B` `A:B` `A B` は同一
- **48文字で切られる**ので長い名前の頭が同じだと衝突
- 改名は全画像のサイドカーに書かれた `crawl:<名前>` を書き換える必要がある

## 4. 今日入れた修正(作り直しでも残す価値がある)

- 同名で新規作成したら 409 で断る。黙って上書きして元の目標を失うのを止めた
- 収集の主語は**目標が最優先**。フォルダ名は目標が空のときの代用
  (以前はフォルダ名が ASCII のときだけ目標を見ていたので、日本語名のフォルダは目標が無視されていた)
- 生成の実況は、そのフォルダが生成している時だけ出す(別フォルダに他所のプロンプトが出ていた)
- `GET/POST /api/groups`, `DELETE /api/groups/{name}` = 空の入れ物を持てるようにした土台
  (`store/albums/_groups.json`)。**UI 未接続**。作り直しで使うか捨てるか判断する

## 5. 作り直しで満たすこと

- **入れ物とタスクを言葉から分ける。** 同じ「フォルダ」で呼ばない
- **空の入れ物が作れる。** ＋ の先で「入れ物 / 集める / 作る」を選べる
- **並び替えができる**(ユーザー要望)。今は名前順固定で、手で並べ替える手段が無い
- **左のリストにブースト中(有料AI使用中)のアイコン**(ユーザー要望)。今は自動/完了/実行中しか出ない
- **同名を許すか決める。** 許すなら識別子を名前から切り離す(内部ID)。
  許さないなら、記号違いが潰れることも含めて作成時に警告する
- **空でも「ある」ことが分かる。** 0枚のフォルダが「できていない」ように見えないこと
- 名前欄に書ける記法(`親/子`)は、**書けるなら画面に明示する**。隠し仕様にしない

## 6. 実装(2026-09-06)

**決定(ユーザー確認済み):** 同名は禁止のまま+作成時に正直な警告(内部ID移行はしない)。
入れ物=**グループ** / タスク=**フォルダ** と呼び分ける。

### サーバ (src/main.rs)
- `_groups.json` が**グループの正本台帳**になった。形は `[{path, order}]`(旧形の文字列配列も読める)。
  `sync_groups()` がタスクの `folder` 欄に現れたパス(祖先含む)を自動登録し、初回は名前昇順で
  order を 10 刻み採番(それまでの見た目を保存)。`/api/albums` と `/api/groups` の両方で走る
- `load_albums()` は `_groups.json` を除外+「name 文字列を持つ object」だけ読む
  (台帳がアルバム一覧に混入して autopilot/prune/lora まで流れるバグの根治)
- `DELETE /api/groups/{name}` は**先に中のフォルダを親へ退避**(`refolder_albums`)してから台帳を消す
  (退避しないと folder 欄から即座に再生成されて「消えない」ように見えていた)
- `/api/folders/rename` は台帳の path にも同じ前方一致置換(order 維持・dedup)
- アルバムに `order: f64` を追加。`api_album_make` の引き継ぎキーに入れたので
  **headAutoSave の部分更新でも消えない**。`POST /api/order {albums:[{name,order}], groups:[{path,order}]}`
  で一括採番(1ドロップ=1リクエスト)

### UI (web/index.html)
- ＋は3択ポップオーバー: **グループ(空の入れ物) / 集める / 作る**。グループはサイドバーその場の
  インライン入力(Enter=作成/Esc=取消、409は入力を残して toast)。グループ行の右クリックにも
  「この中にグループ/集める/作る」「グループを削除(中身は外へ出す)」
- 木は台帳駆動: `buildTree(albumsCache, groupsCache)`。空グループも行として出て、開くと
  「(空のグループ — ＋で中に作成 / フォルダをドラッグ)」
- **並び替え**: 行の上下30%の縁に落とすと挿入線(ins-top/ins-bot)が出て並び替え。中央40%は従来の
  合流/移動のまま。落とすと兄弟全員を10刻みに再採番して `/api/order` へ。order 無しの新規は
  従来どおり一番上(作成順)に湧く。ポインタが行の中(0≤t≤1)の時だけ縁扱い(合成イベント対策)
- **ブースト中はコインアイコン**(SVG)を行に常時表示。⏳と💰💊の絵文字は全部 SVG に置換(憲法6条)
- 作成時の正直表示: 名前欄の下に「保存名は「◯◯」になります(記号は _ に、48文字まで)」
  「「◯◯」はもうあります」を入力のたびに表示(albumSlug = サーバの album_slug の鏡写し)。
  `親/子` 記法はヒントとして明示。最終ガードはサーバの 409 のまま
- アルバム行の「この中に新規フォルダ」(＋)は廃止 — タスク名が勝手にグループ名化する混乱の元だった
- ドラッグ中はサイドバー再描画を止める(`dragNav_` ガード。2秒ポーリングが DOM を壊すのを防ぐ)
